## Requirements
### Requirement: The interface must present core dialogue information
The framework SHALL display the active speaker name, dialogue text, and progression affordances in a consistent in-game HUD.

#### Scenario: Showing a spoken line
- **WHEN** the runtime executes a dialogue command with speaker and text content
- **THEN** the interface renders the speaker label and current line in the dialogue HUD

#### Scenario: Advancing from the HUD
- **WHEN** the player uses the configured advance input while no blocking menu is open
- **THEN** the interface forwards the request to the scenario runtime to reveal or continue the current line

### Requirement: The interface must present interactive choices
The framework SHALL display branching options in a dedicated choice view and prevent unrelated progression until one valid option is selected.

#### Scenario: Opening a choice list
- **WHEN** the runtime reaches a choice command
- **THEN** the interface shows all available options in a selectable list and pauses normal dialogue advancement

#### Scenario: Confirming a choice
- **WHEN** the player activates one of the presented options
- **THEN** the interface closes the choice view and passes the selected option back to the runtime

### Requirement: The interface must expose dialogue history
The framework SHALL keep a readable backlog of previously displayed dialogue entries from the current session.

#### Scenario: Opening the backlog
- **WHEN** the player requests history while dialogue has already been shown
- **THEN** the interface opens a backlog view containing prior speaker and line entries in order

#### Scenario: Recording backlog content
- **WHEN** a dialogue line finishes displaying to the player
- **THEN** the interface records that line into the backlog for later review

### Requirement: The interface must expose basic flow controls and persistence entry points
The framework SHALL provide player-accessible controls for auto mode, skip mode, save, load, and settings access.

#### Scenario: Toggling auto mode
- **WHEN** the player enables auto mode from the interface
- **THEN** the framework continues advancing eligible dialogue lines automatically until interrupted by player input or blocking content

#### Scenario: Opening save or load controls
- **WHEN** the player opens the system menu or dedicated save/load entry point
- **THEN** the interface presents save and load actions without leaving the active framework scene
