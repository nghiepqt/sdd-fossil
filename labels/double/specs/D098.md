# Task Deadline Notifications Specification

> **Note**: This spec supersedes the original "Reminders Inbox" stub spec.
> The reminders concept was re-scoped: rather than a manual reminder CRUD entity,
> `/work/reminders` delivers task deadline notifications derived from existing task data.

## Purpose

Defines the task deadline notification surface at `/work/reminders`. It reads tasks with
`dueDate ≤ today` and `done = false` and groups them into Overdue / Due today sections.
No separate `reminders` table or manual CRUD is required.

## Requirements

### Requirement: Task Deadline Notifications Route Exists

A `/work/reminders` route MUST exist and render without error. It MUST load all tasks via
`getAllTasks()` and classify each by its `dueDate` relative to today's date.

#### Scenario: Route renders without error

- GIVEN the Work module is mounted and the user is authenticated
- WHEN the user navigates to `/work/reminders`
- THEN the page renders without a runtime error

### Requirement: Overdue and Due-Today Grouping

Tasks MUST be classified and grouped:

- **Overdue**: `dueDate < today` AND `done = false`
- **Due today**: `dueDate = today` AND `done = false`
- Tasks where `dueDate` is null or `done = true` MUST be excluded

#### Scenario: Overdue tasks appear in the Overdue card

- GIVEN a task with `dueDate` before today and `done = false`
- WHEN the notification page renders
- THEN that task appears in the Overdue section with a destructive badge showing the date

#### Scenario: Due-today tasks appear in the Due today card

- GIVEN a task with `dueDate = today` and `done = false`
- WHEN the notification page renders
- THEN that task appears in the Due today section with a secondary badge

#### Scenario: Completed tasks are excluded

- GIVEN a task with `dueDate` in the past and `done = true`
- WHEN the notification page renders
- THEN that task does NOT appear in either section

### Requirement: Empty State

When no tasks are overdue or due today, a user-visible empty state MUST be shown.

#### Scenario: Empty state shown when no pending tasks

- GIVEN no tasks are overdue or due today
- WHEN the notification page renders
- THEN an empty state message is displayed and no error is thrown

### Requirement: Work Dashboard Callout

The Work dashboard at `/work` MUST show a notification callout summarising overdue tasks,
with a link to `/work/reminders` for the full list.

#### Scenario: Overdue count badge on Work dashboard

- GIVEN at least one overdue task exists
- WHEN the Work dashboard renders
- THEN a destructive badge with the overdue count is visible in the Notifications card

### What This Spec Does NOT Cover

- Standalone manual reminder entries (Notion A.M.R.-style inbox) — not implemented
- Time-of-day snooze or recurrence
- A `reminders` Supabase table — the original schema stub is no longer required by this feature
