## Requirements
### Requirement: Markdown code-block output

The `execute_ssh_command` tool SHALL format command output using fenced markdown code blocks instead of `===`-style separators. Fence length SHALL be chosen dynamically so that output containing backtick runs does not break the enclosing fence.

#### Scenario: Successful command output is fenced
- **WHEN** a command succeeds with stdout and/or stderr
- **THEN** the response presents the command, stdout, and (if present) stderr inside fenced code blocks
- **AND** no `===` separator lines appear in the response

#### Scenario: Output containing backticks does not break the fence
- **WHEN** stdout contains a run of three or more backticks
- **THEN** the enclosing fence uses a backtick run at least one longer than the longest run in the content

### Requirement: Per-command log file

The system SHALL write a log file for each `execute_ssh_command` invocation containing the target host, the command, full untruncated stdout and stderr, the exit code, and timing information. Each invocation SHALL produce a uniquely named file so concurrent or repeated commands do not overwrite each other.

#### Scenario: Log file captures full output
- **WHEN** a command is executed and produces output exceeding `max_length`
- **THEN** the log file contains the complete untruncated stdout and stderr
- **AND** the MCP response contains output truncated to `max_length`

#### Scenario: Log path surfaced in response
- **WHEN** a command is executed and logging is enabled
- **THEN** the MCP response includes the absolute path to the log file for that command

### Requirement: Configurable log directory with OS-aware defaults

The log directory SHALL be configurable via the `SSH_MCP_LOG_DIR` environment variable. When the variable is unset, the system SHALL use an OS-appropriate default: `~/Library/Logs/ssh-mcp/` on macOS, `${XDG_STATE_HOME:-~/.local/state}/ssh-mcp/logs/` on Linux, and `%LOCALAPPDATA%\ssh-mcp\logs\` on Windows.

#### Scenario: Custom directory honored
- **WHEN** `SSH_MCP_LOG_DIR` is set to a writable directory path
- **THEN** log files are written under that directory

#### Scenario: OS default used when unset
- **WHEN** `SSH_MCP_LOG_DIR` is not set
- **THEN** the system resolves the default directory for the current operating system and writes logs there

### Requirement: Logging disable switch

When `SSH_MCP_LOG_DIR` is set to `false` (case-insensitive), the system SHALL NOT create or write any log file, and the response SHALL NOT reference a log path.

#### Scenario: Logging disabled
- **WHEN** `SSH_MCP_LOG_DIR` is set to `false`
- **THEN** no log file is created
- **AND** the MCP response contains command output but no log path reference

### Requirement: Logging degrades gracefully

A failure to create or write the log file SHALL NOT prevent the command from executing or its output from being returned. The response SHALL note that logging was skipped.

#### Scenario: Log directory not writable
- **WHEN** the configured log directory cannot be created or written
- **THEN** the command still executes and returns its output
- **AND** the response indicates that logging was skipped

### Requirement: Bounded-memory output handling

The system SHALL read remote command output in bounded chunks rather than buffering the entire stream in memory before truncation, so that a command producing unbounded output cannot exhaust memory and crash the MCP server process.

#### Scenario: Runaway command does not crash the server
- **WHEN** a remote command produces output far larger than `max_length` (e.g. a continuous stream)
- **THEN** memory held for the response is bounded by `max_length`
- **AND** the MCP server process remains alive to serve subsequent requests

#### Scenario: Non-UTF-8 output does not crash the server
- **WHEN** a command emits bytes that are not valid UTF-8
- **THEN** decoding does not raise an unhandled exception
- **AND** the command returns output with invalid sequences replaced

### Requirement: Concise tool and server descriptions

The MCP server `instructions` and all tool docstrings SHALL be concise to reduce token consumption by the client, while still clearly stating each tool's purpose and parameters.

#### Scenario: Descriptions remain informative
- **WHEN** an MCP client reads the server instructions and tool descriptions
- **THEN** each tool's purpose and required parameters are clearly identifiable
- **AND** the descriptions avoid redundant or verbose phrasing
