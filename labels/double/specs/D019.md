## Purpose

Keeps admin-only navigation links out of sight for anyone who isn't authenticated as an admin, purely as a UX cleanliness measure — actual access control still lives at the API layer (`get_admin()`), which rejects non-admin requests regardless of what the nav shows.

## Requirements

### Requirement: Admin nav links shown only with a valid admin token
`farpost-web/components/SiteNav.tsx` SHALL read `adminToken` from the Zustand auth store (`useAuthStore`) and conditionally render the admin nav links (Intelligence, Role Types, Professionals, Admins). These links SHALL be visible only when `adminToken` is present (post-mount, to avoid an SSR/hydration mismatch). There is no `is_admin` flag on the professional or adjuster record, and no separate adjuster-specific layout — `adminToken` is a distinct admin-identity JWT issued by the unified login endpoint (`POST /api/v1/auth/login`) when the submitted credentials match an `Admin` document, not any field on `Professional`.

#### Scenario: Authenticated admin sees admin nav links
- **WHEN** a user is authenticated with a valid `adminToken`
- **THEN** the Intelligence, Role Types, Professionals, and Admins nav links are visible in `SiteNav`

#### Scenario: Professional (non-admin) does not see admin nav links
- **WHEN** a user is authenticated only with a professional `token` (no `adminToken`), or is unauthenticated
- **THEN** none of the admin nav links are rendered in `SiteNav`

#### Scenario: API still enforces admin access regardless of nav state
- **WHEN** a request without a valid admin JWT calls any `/api/v1/admin/...` endpoint
- **THEN** the API returns `401`/`403` via the `get_admin()` dependency (`app/middleware/auth.py`) — unchanged by what the nav displays
