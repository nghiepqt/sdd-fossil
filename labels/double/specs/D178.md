## Requirements
### Requirement: PromptFrame 组装
系统 SHALL 通过结构化 PromptFrame 组装模型输入，并明确区分 system instructions、workflow instructions、node instructions、当前用户输入、变量池值、最近对话轮次、摘要、召回记忆、RAG 证据、工具 trace 和 omissions。

#### Scenario: 组装 LLM 节点上下文
- **WHEN** LLM 节点在启用上下文编排的情况下准备模型请求
- **THEN** 系统 SHALL 在构造 provider-specific chat messages 前先构建 PromptFrame

#### Scenario: 组装 Agent 上下文
- **WHEN** Agent 节点在启用上下文编排的情况下准备 ReAct 模型请求
- **THEN** 系统 SHALL 在 PromptFrame 中包含当前 query、工具描述、相关输入、召回记忆和受限 scratchpad 上下文

### Requirement: 上下文预算分配
系统 SHALL 在 PromptFrame 各 section 之间分配可配置 token 预算，并 SHALL 在保留可选召回内容前优先保留必需 section。

#### Scenario: 必需 section 优先适配
- **WHEN** 上下文预算受限
- **THEN** 系统 SHALL 在可选历史、记忆、RAG 或工具 trace 之前，优先保留 system instructions、node instructions、当前用户输入和必需变量值

#### Scenario: 裁剪可选 section
- **WHEN** 可选上下文超过其分配预算
- **THEN** 系统 SHALL 裁剪、摘要或省略低排序可选项，并在 PromptFrame metadata 中记录 omission

### Requirement: 对话压缩
系统 SHALL 将长对话历史压缩为类型化摘要，同时保留最近轮次和继续任务所需的关键事实。

#### Scenario: 压缩较旧轮次
- **WHEN** 对话历史超过配置的轮次数或 token 阈值
- **THEN** 系统 SHALL 将较旧轮次摘要为 rolling summary，并逐字保留最近配置轮次

#### Scenario: 保留任务关键字段
- **WHEN** 对话历史被压缩
- **THEN** 摘要 SHALL 在存在时保留显式用户请求、约束、决策、开放任务、错误和最终回答

### Requirement: 工具 trace 压缩
系统 SHALL 在 Agent 工具 trace 和大型 observation 注入模型上下文或提取为记忆前进行压缩。

#### Scenario: 压缩大型 observation
- **WHEN** 工具 observation 超过配置大小阈值
- **THEN** 系统 SHALL 保留工具名称、action input 摘要、关键结果字段、citation 或资源标识，以及事件引用，而不是注入完整原始 payload

#### Scenario: 保留知识库引用
- **WHEN** 知识库检索 observation 被压缩
- **THEN** 系统 SHALL 在配置预算内保留文档标识、标题、分数和引用内容片段

### Requirement: 上下文来源隔离
系统 SHALL 对指令、用户/会话历史、工作流变量、Agent 记忆、RAG 知识和工具 observation 等上下文来源进行标记并保持区分。

#### Scenario: 区分记忆与 RAG
- **WHEN** 召回记忆和知识库检索结果同时被纳入上下文
- **THEN** 系统 SHALL 将记忆标记为交互派生状态，将 RAG 标记为文档派生知识

#### Scenario: 调试上下文来源
- **WHEN** PromptFrame 在 debug 模式下被记录或检查
- **THEN** 系统 SHALL 暴露 section 名称、source id、token 估算和 omitted items，并避免混淆来源类别

### Requirement: Provider 请求转换
系统 SHALL 将 PromptFrame 转换为 provider 兼容的 chat messages，并保持 section 顺序和必需上下文不丢失。

#### Scenario: 转换为 OpenAI-style messages
- **WHEN** PromptFrame 通过 OpenAI-style integration 发送
- **THEN** 系统 SHALL 将 system instructions 映射为 system messages，并将面向用户的组装上下文映射为 provider 兼容的有序 user 或 assistant messages

#### Scenario: 关闭时保持当前行为
- **WHEN** 上下文编排未启用
- **THEN** 系统 SHALL 使用现有请求构造路径，并保持当前模型请求行为

### Requirement: 上下文压力处理
系统 SHALL 在模型调用前检测上下文压力，并在发送请求前应用配置的压缩、召回缩减和 omission 规则。

#### Scenario: token 估算超过阈值
- **WHEN** 估算 prompt tokens 超过配置的上下文阈值
- **THEN** 系统 SHALL 在创建 provider 请求前执行压缩和可选上下文缩减

#### Scenario: 压缩后仍无法适配上下文
- **WHEN** 压缩后必需 section 仍超过最大预算
- **THEN** 系统 SHALL 返回清晰的上下文预算错误，而不是静默丢弃必需用户输入或节点指令

### Requirement: 上下文可观测性
系统 SHALL 为 PromptFrame 大小、选中的记忆、压缩动作、省略 section 和 token 使用情况提供运行时可观测性。

#### Scenario: 记录预算报告
- **WHEN** 模型请求通过上下文编排组装
- **THEN** 系统 SHALL 生成预算报告，包含按 section 估算的 tokens、压缩动作、召回记忆数量和 omitted item 数量

#### Scenario: 对比估算与实际 usage
- **WHEN** provider 返回 token usage
- **THEN** 系统 SHALL 暴露实际 usage，用于调优上下文预算和压缩阈值
